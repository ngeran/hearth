# M1 — Auth and profile

Goal: a new person can create an account, finish onboarding, and sign back in on a second device.
Profiles are private by default, the API validates every input, and Greek/English stay at parity.

This file is also the milestone progress ledger. If work has to restart, read `CLAUDE.md`, then this
file, then continue from the first unchecked item. Do not assume chat history exists.

## Scope (M1 only)

- Better Auth with email one-time code and passkeys. No passwords.
- Onboarding: display name, R2 photo, approximate area, move-in window, budget range, seeking,
  120–300 character bio, 18+ confirmation.
- M1 additions: life stage (student / first-time mover / independent / other), campus picker,
  academic-email verification by one-time code, language preference stored on the profile.
- Profile edit, photo replace/remove, passkey management, data export (JSON), account deletion.
- All user-facing strings in `apps/web/src/locales/en.json` and `el.json`.
- 360 px layout, keyboard and screen-reader checks; empty, loading and error states.

## Acceptance

- New user signs up with an email code, completes onboarding, and signs in on a second device.
- Authorization tests pass: unauthenticated requests are rejected and one user cannot read or change
  another user's profile, photo, verification or export.
- `pnpm check:i18n`, `pnpm typecheck`, `pnpm lint`, shared tests and the web build pass locally.
- Worker tests and Playwright pass in CI (see the Android limitation in `CLAUDE.md`). The M1-specific
  Worker and Playwright tests are deferred at the user's request; record them as open work, not as done.

## Decisions (append-only; keep reasons)

- Better Auth `1.7.20` with `@better-auth/drizzle-adapter@1.7.20` and
  `@better-auth/passkey@1.7.20`; email OTP plugin, hashed OTP storage.
- Map Better Auth's `user` model to the existing `users` table with
  `schema: { ...schema, user: schema.users }`. No duplicate auth user table.
- Auth mounts at `/api/auth/*`; app endpoints stay under `/api/v1/*`.
- Mail goes through a small fetch-based `Mailer` and Resend's HTTP API. No Resend SDK dependency.
  Emails are bilingual EN/EL. OTPs and message bodies are never logged.
- Academic-email verification is our own flow: 6 digits, HMAC-SHA256 hash at rest, 10-minute TTL,
  5 attempts, 60-second resend cooldown, one active challenge per user.
- Account deletion is our own `DELETE /api/v1/me` with a typed confirmation string, explicit
  DB/R2 cleanup and an anonymized audit row. Better Auth's delete flow requires a fresh session and
  is not suitable for this product.
- Photo uploads accept JPEG/PNG only. The client re-encodes to JPEG; the Worker sniffs magic bytes and
  strips metadata with pure functions in `packages/shared`. Max 5 MB.
- Test-only OTP: when `ENVIRONMENT === "test"` and `AUTH_TEST_OTP` is set, both the Better Auth email
  code and the academic code use that fixed value. Production uses secure random generation. The
  test OTP is never returned in an API response.
- `react-hook-form` + `@hookform/resolvers` justify: consistent validation/error wiring across the
  onboarding wizard and profile form, with the same Zod schemas as the server.
- Dates that are calendar days (move-in window) are `YYYY-MM-DD` text, not unix timestamps.
  Everything that is an instant is unix seconds, UTC.
- Approximate area is a human label plus optional coordinates rounded to 2 decimals (~1–2 km).
  Exact addresses are never collected or stored.
- `migrations/0000_initial.sql` stays untouched. M1 adds `0001_auth_profiles.sql`.
- 2026-11-11 — M1 Worker and Playwright tests were started and then deferred at the user's request.
  The partial scaffold was reverted; do not re-add it without an explicit request. Shared unit tests and
  the pre-existing Worker health test remain in CI.
