# M7 — Admin operations console

Status: built 2026-11-15; pending owner `ADMIN_EMAILS` secret + staging spot-check. Builds on M1–M6. Owner-facing operator console for users,
listings, errors, and activity metrics.

## Goal

Give the owner one calm, authenticated surface to answer four questions and act on the
first three:

1. **How is the app doing?** Registration, completeness, presence, listings, matches,
   chat, push and error counts.
2. **Who is having trouble?** Look up a user, see their state, revoke sessions or delete
   the account.
3. **What content is live?** Browse listings and delete one.
4. **What is breaking?** Inspect recent server errors (scrubbed).

## Non-goals

- No support-ticket inbox, no admin replies to users (owner approved user lookup +
  actions only; users still reach the owner by email).
- No message bodies, no chat transcripts, no profile photos in the console.
- No user impersonation, no editing a user's profile or listings in place.
- No third-party analytics, error SaaS, or tracking scripts.
- No new dependencies.

## Decisions (approved 2026-11-15)

| #   | Decision        | Choice                                                                              | Why                                                                                                              |
| --- | --------------- | ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 1   | Console surface | `/admin/*` React routes in `apps/web`; API under `/api/v1/admin/*`                  | Reuses auth, React, i18n and the design system; no second app to deploy.                                         |
| 2   | Access control  | `ADMIN_EMAILS` env allowlist, case-insensitive comma list                           | Zero migration, instant revoke, fail-closed when unset. `users.role` stays for future roles but is not the gate. |
| 3   | Scope           | User lookup + actions; listing moderation; error inspection                         | Matches the closed-tester support needs without building a helpdesk.                                             |
| 4   | Error capture   | `error_events` D1 table, scrubbed and capped                                        | In-console, privacy-safe, no third party. 30-day retention.                                                      |
| 5   | Online metric   | `users.last_seen_at` touched at most once per 5 minutes; online = within 15 minutes | No heartbeat endpoint, no traffic, bounded writes.                                                               |
| 6   | Match metric    | Impression rows in `match_events`; success = a thread exists for the pair           | The raw signals already exist (`chat_threads`); impressions make "shown but never started" measurable.           |

## Access model

- `/api/v1/admin/*` uses `requireAdmin`: it performs its own session lookup and returns
  **404 with the standard `not_found` body** when there is no session or the email is not
  allowlisted. Non-admins cannot distinguish admin routes from unknown routes.
- Unset or empty `ADMIN_EMAILS` means nobody is an admin (fail closed).
- `ADMIN_EMAILS` is a secret (Wrangler secret binding), never a committed value;
  `.dev.vars.example` documents it.
- `requireSameOrigin` already covers every `/api/v1/*` write.
- Every mutation writes an `audit_log` row (`admin.user.sessions.revoke`,
  `admin.user.delete`, `admin.room.delete`) with the admin as `actor_user_id` and the
  target id in metadata — no emails or content in metadata.
- The admin cannot delete their own account from the console (generic 400).

## Data model (migration 0007)

```sql
ALTER TABLE users ADD COLUMN last_seen_at integer NOT NULL DEFAULT 0;
CREATE INDEX idx_users_last_seen ON users (last_seen_at);

CREATE TABLE error_events (
  id text PRIMARY KEY,
  created_at integer NOT NULL,
  request_id text,
  method text NOT NULL,
  route text NOT NULL,
  status integer NOT NULL,
  error_name text NOT NULL,
  message text NOT NULL
);
CREATE INDEX idx_error_events_created ON error_events (created_at);
CREATE INDEX idx_error_events_route_created ON error_events (route, created_at);

CREATE TABLE match_events (
  viewer_id text NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  candidate_id text NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  created_at integer NOT NULL,
  PRIMARY KEY (viewer_id, candidate_id)
);
CREATE INDEX idx_match_events_created ON match_events (created_at);
CREATE INDEX idx_match_events_candidate ON match_events (candidate_id);
```

- `last_seen_at` is unix seconds, `0` until first touch.
- `error_events` stores no headers, no query string, no user id. `message` is capped at
  200 characters and scrubbed of emails and long token-like strings.
- `match_events` is directed (viewer → candidate) and keeps the **first** impression
  only (`INSERT OR IGNORE`), which is the clock for "no thread within 7 days".
- Rows cascade with either user; account deletion needs no new purge branch.
- Retention: the errors listing deletes rows older than 30 days before answering
  (`waitUntil`), so the table stays bounded without a cron trigger.

## API

All endpoints require the admin session described above. List endpoints validate query
parameters with Zod; every response is parsed with a shared schema before sending.

| Method + path                                     | Purpose                                                                 |
| ------------------------------------------------- | ----------------------------------------------------------------------- |
| `GET /api/v1/admin/overview`                      | Aggregates for the dashboard.                                           |
| `GET /api/v1/admin/users?query=&offset=&limit=`   | Search by email or display name, newest first.                          |
| `GET /api/v1/admin/users/:id`                     | User, profile summary, counts, recent threads, listings.                |
| `POST /api/v1/admin/users/:id/sessions/revoke`    | Delete every session row for the user.                                  |
| `POST /api/v1/admin/users/:id/delete`             | Body `{ confirmEmail }`; runs the same deletion as `DELETE /api/v1/me`. |
| `GET /api/v1/admin/errors?route=&status=&offset=` | Scrubbed error rows, newest first.                                      |
| `GET /api/v1/admin/rooms?status=&query=&offset=`  | Listings with lister contact.                                           |
| `POST /api/v1/admin/rooms/:id/delete`             | Deletes the listing rows and its R2 photos.                             |

`GET /api/v1/me` gains `isAdmin: boolean` (from `ADMIN_EMAILS`) so the shell can show
the admin entry without an extra probe request.

## Metrics

All times are unix seconds, UTC.

- **Online** — `users.last_seen_at >= now - 15 min`. `requireSession` runs a conditional
  `UPDATE users SET last_seen_at = now WHERE id = ? AND last_seen_at < now - 5 min` inside
  `waitUntil`, so at most one write per user per five minutes and no added latency.
- **Registrations** — `users.created_at` today (UTC midnight), 7 days, 30 days.
- **Complete profiles** — `profiles.onboarding_completed_at IS NOT NULL`.
- **Academic verified** — `profiles.academic_email_verified_at IS NOT NULL`.
- **Listings** — `rooms` total and `status = 'active'`.
- **Match impressions (7 d)** — `match_events.created_at >= now - 7 d`.
- **Successful pairs** — `chat_threads` rows (a thread only exists after a mutual say-hi).
- **Unsuccessful pairs** — `match_events` older than 7 days with no `chat_threads` row for
  the pair in either direction.
- **Threads active (7 d)** — `chat_threads.updated_at >= now - 7 d`.
- **Push subscriptions** — `push_subscriptions` rows.
- **Errors** — `error_events` in the last 24 h / 7 d, plus the newest timestamp.

## UI

New routes inside the authenticated shell (`RequireAuth` + admin check), rendered by an
`AdminShell` with a tab bar and a back-to-app link:

- `/admin` — metric cards (users, presence, listings, matches, chat, push, errors) and the
  five newest errors, each linking to `/admin/errors`.
- `/admin/users` — search field, list with status chips, link to detail.
- `/admin/users/:id` — profile summary, counts, recent threads, listings, actions
  (revoke sessions; delete with an email-confirmation dialog).
- `/admin/errors` — filters by route/status, newest first, empty/loading/error states.
- `/admin/rooms` — listings with status filter; "Delete" action with confirmation.

A non-admin who opens any `/admin` route sees the standard not-found page. The sidebar
shows the admin link only when `me.isAdmin` is true. Reuse `PageLoading`/`PageError`,
`Button`, form controls, the existing tokens; no new colors or font sizes.

## i18n

New `admin.*` section in `en.json` and `el.json`, native Greek, same key set. Numbers are
formatted with `Intl.NumberFormat(i18n.resolvedLanguage)`; timestamps with
`Intl.DateTimeFormat`. No interpolated message fragments from the API are rendered.

## Acceptance

- A signed-in non-admin gets 404 on every admin endpoint and route.
- An allowlisted admin sees correct aggregates on seeded data (checked by hand on a
  local DB with the seed script).
- Revoking sessions signs the target user out; deleting removes D1 rows, R2 objects,
  DO bodies and writes an audit row; removing a listing hides it from browse.
- A thrown 500 creates exactly one scrubbed `error_events` row and still returns the
  standard error body.
- Full gate green: typecheck, lint, build, i18n parity, unit tests, e2e.
